## 📐 Mathematical Foundations: Relative Orbital Mechanics

### 1. Clohessy-Wiltshire (CW / Hill) Equations
In Low Earth Orbit (LEO), proximity operations between the Chaser (ASTRA) and the Target (debris/station) are expressed in the **Local-Vertical Local-Horizontal (LVLH)** coordinate frame:
* $+x$ (Radial): Directed from Earth center outwards towards the satellite.
* $+y$ (In-Track / V-Bar): Directed along the velocity vector of the target.
* $+z$ (Cross-Track / H-Bar): Normal to the orbital plane (along angular momentum vector).

The linearized relative equations of motion for circular orbits are:
$$\ddot{x} - 2\omega \dot{y} - 3\omega^2 x = f_x / m$$
$$\ddot{y} + 2\omega \dot{x} = f_y / m$$
$$\ddot{z} + \omega^2 z = f_z / m$$

Where:
* $\omega = \sqrt{\mu / r^3}$ is the mean orbital angular velocity ($\text{rad/s}$).
* $f_x, f_y, f_z$ are the control thrust forces generated by our cold-gas micro-thrusters.
* $m$ is the instantaneous satellite mass ($m_0 - \Delta m_{\text{propellant}}$).

### 2. State Transition Matrix $\mathbf{\Phi}(t)$
The continuous unforced solution is solved deterministically using:
$$\mathbf{X}(t) = \mathbf{\Phi}(t) \mathbf{X}_0$$
$$\mathbf{\Phi}_{rr}(t) = \begin{bmatrix} 4 - 3\cos\omega t & 0 & 0 \\ 6(\sin\omega t - \omega t) & 1 & 0 \\ 0 & 0 & \cos\omega t \end{bmatrix}$$
$$\mathbf{\Phi}_{rv}(t) = \begin{bmatrix} \frac{1}{\omega}\sin\omega t & \frac{2}{\omega}(1 - \cos\omega t) & 0 \\ \frac{2}{\omega}(\cos\omega t - 1) & \frac{4}{\omega}\sin\omega t - 3t & 0 \\ 0 & 0 & \frac{1}{\omega}\sin\omega t \end{bmatrix}$$

### 3. ZEM/ZEV (Zero-Effort-Miss / Zero-Effort-Velocity) Optimal Guidance
To steer ASTRA into the docking corridor with minimal fuel consumption, the acceleration command $\mathbf{a}_{\text{cmd}}$ is:
$$\mathbf{a}_{\text{cmd}} = \frac{6}{t_{\text{go}}^2} \mathbf{ZEM} - \frac{2}{t_{\text{go}}} \mathbf{ZEV}$$
Where $t_{\text{go}}$ is the time-to-go until rendezvous.

## 📡 Telemetry Packet Schema (`schemas/telemetry.py`)

Every packet streamed over WebSockets or logged to the mission archive follows this strict structure:

```python
from pydantic import BaseModel, Field
from typing import List, Literal
from datetime import datetime

class ChaserTelemetry(BaseModel):
    position: List[float] = Field(..., description="[x, y, z] in LVLH meters")
    velocity: List[float] = Field(..., description="[vx, vy, vz] in m/s")
    quaternion: List[float] = Field(..., description="[q0, q1, q2, q3] attitude")
    angular_rate: List[float] = Field(..., description="[wx, wy, wz] in deg/s")
    fuel_remaining_kg: float = Field(..., description="Cold-gas N2 mass")
    delta_v_remaining_ms: float = Field(..., description="Remaining delta-V budget")
    battery_pct: float = Field(..., description="Battery State of Charge 0-100%")
    bus_voltage_v: float = Field(28.0, description="Main avionics bus voltage")
    reaction_wheels_rpm: List[float] = Field(..., description="[Rx, Ry, Rz] RPM")
    npu_temp_c: float = Field(..., description="Jetson Orin core temperature")

class TargetTelemetry(BaseModel):
    distance_meters: float
    relative_velocity_ms: float
    koz_status: Literal["NOMINAL", "APPROACH_CORRIDOR", "BREACH"]
    docking_alignment_error_deg: float
    ai_confidence: float

class TelemetryPacket(BaseModel):
    timestamp: str
    met_seconds: float
    phase: Literal[
        "STANDBY", 
        "PHASING", 
        "APPROACH", 
        "INSPECTION", 
        "CAPTURE", 
        "DEORBIT", 
        "ABORT"
    ]
    chaser: ChaserTelemetry
    target: TargetTelemetry
    gnc_mode: Literal["AUTONOMOUS", "MANUAL_OVERRIDE", "ABORTING"]
```

## 🛡️ Safety Interlocks & GNC State Machine (`gnc/state_machine.py`)

The state machine manages the mission lifecycle with strict programmatic guards:

1. **`STANDBY` $\rightarrow$ `PHASING`**:
   * *Guard:* All subsystem health checks = `OK`, Battery $> 85\%$, NavIC lock acquired, Propellant $> 1.8\text{ kg}$.
2. **`PHASING` $\rightarrow$ `APPROACH`**:
   * *Guard:* Distance to target $\le 100\text{ m}$, Relative speed $\le 0.5\text{ m/s}$, Optical keypoint confidence $> 90\%$.
3. **`APPROACH` $\rightarrow$ `INSPECTION`**:
   * *Guard:* Distance $\le 15\text{ m}$, Chaser holds stable relative position on V-bar within $\pm 0.2\text{ m}$.
4. **`INSPECTION` $\rightarrow$ `CAPTURE`**:
   * *Guard:* Target spin rate measured and matched to $< 0.5^\circ/\text{s}$, Docking axis alignment error $< 2.0^\circ$, Closing speed $< 0.10\text{ m/s}$.
5. **`ANY` $\rightarrow$ `ABORT`**:
   * *Trigger:* Commanded via `/api/v1/commands/abort` OR Keep-Out Zone breach without deceleration OR sensor dropout $> 500\text{ ms}$.
   * *Action:* Instantaneous $100\%$ thruster firing in $-y$ direction to escape the collision trajectory.

## 🚀 REST & WebSocket API Specification

### 1. Real-Time Telemetry Stream
* **`WS /ws/telemetry`**
  * Accepts WebSocket connection from Ground Control Station.
  * Streams `TelemetryPacket` at 20 Hz (50 ms intervals).
  * Handles client disconnection gracefully without leaking memory.

### 2. Telecommand Endpoints
* **`POST /api/v1/commands/phase`**
  * Body: `{"target_phase": "APPROACH"}`
  * Evaluates state machine guards. If guards pass, advances state and returns `200 OK`. If guards fail, returns `400 Bad Request` with exact violation details.
* **`POST /api/v1/commands/abort`**
  * Body: `{"reason": "Manual operator abort command"}`
  * Highest priority endpoint. Overrides autonomous planner and triggers immediate retrograde abort burn.
* **`POST /api/v1/commands/gripper`**
  * Body: `{"action": "ENGAGE_ELECTRO_ADHESIVE"}`
  * Simulates/actuates the bio-inspired gripper capture sequence.
* **`GET /api/v1/orbit/predicted_path`**
  * Returns an array of predicted $[x, y, z]$ coordinates over the next $600\text{ seconds}$ calculated via CW equations for 3D trajectory rendering.
